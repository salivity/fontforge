FontForge SubFamily Name Field Explained

This article examines the purpose and importance of the SubFamily name field in FontForge, a key parameter within the OpenType name table. It explains how this metadata field defines a font's specific style variant—such as Regular, Bold, or Italic—and how it enables operating systems and desktop publishing applications to correctly group, display, and toggle different weights and slants within a unified font family.

In FontForge, the SubFamily name field corresponds to Name ID 2 in standard TrueType and OpenType font specification tables. Accessible through the "Font Info" window under the "TTF Names" category, this field identifies the specific style, weight, or slant of an individual font file relative to its overarching Family Name (Name ID 1).

The primary role of the SubFamily name is to establish the style hierarchy within software interfaces. When an application loads a font, it uses the Family Name to create the main font menu entry and reads the SubFamily name to populate the accompanying style selection menu. For example, if the Family Name is set to "MyFont" and the SubFamily name is set to "Light Italic," modern operating systems will categorize the file under the "MyFont" family with "Light Italic" as an available variant rather than listing it as a completely detached typeface.

The SubFamily name is also critical for supporting standard document shortcuts and toggle functions. Under the legacy Windows font-family model, standard families are restricted to four basic styles: Regular, Italic, Bold, and Bold Italic (often abbreviated as the "RIBBI" group). Assigning these exact strings in the SubFamily field allows word processors and operating systems to accurately map standard user commands—such as the Ctrl+B or Ctrl+I shortcuts—to the appropriate font files without artificially slanting or emboldening the glyphs.

For extended font families that feature additional weights like Thin, Medium, SemiBold, or Black, FontForge relies on this field in conjunction with the Typographic SubFamily name (Name ID 17). Setting the standard SubFamily correctly ensures that legacy systems do not break, while modern design suites can recognize the complete spectrum of styles.

Properly setting the SubFamily name prevents font installation errors and system conflicts. If two distinct font files share the same Family Name and SubFamily name, the operating system treats them as identical, leading to cache conflicts, missing styles, or one font file overwriting the other during installation.
