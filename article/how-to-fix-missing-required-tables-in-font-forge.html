How to Fix Missing Required Tables in FontForge

This guide explains how to identify and resolve validation errors related to missing required OpenType and TrueType tables in FontForge. These errors occur when a font lacks mandatory structural data—such as the OS/2, cmap, head, hhea, maxp, or post tables—required by font rendering engines. Following the steps below will ensure your font metadata, encodings, and export settings are correctly configured so FontForge can automatically generate all required tables.

1. Identify the Specific Missing Table

Run FontForge's built-in validator to determine which table is failing:

  1. Open your font in FontForge.
  2. Navigate to Element > Validation > Validate.
  3. Review the validation window for messages explicitly citing missing tables (e.g., Missing required table: 'OS/2' or Missing table: 'cmap').

2. Configure Font Information and Metadata

Most missing tables result from incomplete metadata, which prevents FontForge from generating proper table headers.

  1. Go to Element > Font Info.
  2. Select the PS Names tab and ensure Fontname, Family Name, and Name for Humans are populated without unsupported symbols.
  3. Select the TTF Names tab and verify that default entries for English (US) exist for:
    • Copyright
    • Font Family Name
    • Font Subfamily Name
    • Unique Font Identifier
    • Full Font Name
    • Version
  4. Click OK to apply changes.

3. Populate OS/2 and Metric Tables

If the OS/2 or hhea tables are reported missing:

  1. Navigate back to Element > Font Info > OS/2.
  2. In the Misc. sub-tab, assign a valid Weight class (e.g., 400 for Regular) and Width class (e.g., Medium/Normal).
  3. Ensure a 4-character Vendor ID is present (use PfEd or any four alphanumeric characters).
  4. Go to the Metrics sub-tab under OS/2 and click Set Offset or compute values automatically for Win Ascent, Win Descent, Typo Ascent, and Typo Descent.
  5. Check the Panose sub-tab and set basic classification metrics instead of leaving all values at zero.

4. Fix Encoding for the cmap Table

A missing cmap table indicates that the glyphs are not mapped to standard character codes:

  1. Go to Encoding > Reencode.
  2. Select ISO 10646-1 (Unicode, BMP) or Unicode (Full).
  3. Ensure that basic glyphs (such as the space character uni0020 and standard Latin characters) have assigned Unicode codepoints and are not placed in unassigned slots.
  4. Ensure the .notdef glyph exists at glyph index 0, as TrueType and OpenType specifications require it.

5. Adjust Font Generation Settings

FontForge compiles most low-level tables (head, maxp, post, loca) at the time of export. If custom generation options are stripping these tables:

  1. Go to File > Generate Fonts.
  2. Choose TrueType or OpenType (CFF) from the format dropdown.
  3. Click the Options button next to the format selection.
  4. Verify that:
    • OpenType is checked if outputting OTF fonts.
    • Any options specifying "Don't create OS/2 table" or stripping TrueType tables are unchecked.
    • Apple or OpenType table format is selected according to your target platform.
  5. Click OK, then click Generate.

After completing these steps, reopen the newly generated font file in FontForge and run Element > Validation > Validate again to confirm that all required tables are present and valid.
