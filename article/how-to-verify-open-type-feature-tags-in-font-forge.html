How to Verify OpenType Feature Tags in FontForge

This guide demonstrates how to verify that your OpenType feature tags comply with official OpenType specifications using FontForge. You will learn how to navigate the Font Info lookups interface, cross-reference feature tags against registered standards, validate script and language system assignments, and use FontForge’s built-in validation tools to catch formatting errors before exporting your font.

OpenType Feature Tag Requirements

OpenType feature tags are four-character identifiers (such as liga for standard ligatures, kern for kerning, or smcp for small capitals) defined by the OpenType specification maintained by Microsoft and Adobe. To comply with the standard:

  • Tags must be exactly four ASCII characters long (shorter tags must be padded with trailing spaces, such as c2sc).
  • Standard tags must consist of lowercase alphanumeric characters.
  • Custom, application-specific tags typically start with an uppercase letter or follow private-use conventions, though standard renderers may ignore non-registered tags.

Step 1: Open the Lookups Interface

  1. Launch FontForge and open your font project (.sfd, .otf, or .ttf).
  2. Go to the menu bar and select Element > Font Info (or press Ctrl+Shift+F on Windows/Linux, Cmd+Shift+F on macOS).
  3. In the sidebar on the left, click on Lookups.

The Lookups panel contains two primary tables: GSUB (Glyph Substitution) and GPOS (Glyph Positioning). Both use OpenType feature tags to control typography behavior.

Step 2: Inspect Lookup Metadata and Feature Tags

  1. Under either the GSUB or GPOS tab, click the + icon to expand the lookups list.
  2. Select a lookup and click the Edit Metadata button on the right (or double-click the lookup).
  3. Switch to the Features tab inside the lookup dialog.
  4. Review the Feature column:
    • FontForge includes a built-in dropdown menu containing officially recognized OpenType tags. Click the field to see if your tag appears within FontForge's predefined list.
    • If you typed a tag manually, verify that it matches the exact 4-character casing found in the official OpenType specification.
    • Ensure that the feature is mapped to valid Script and Language combinations (e.g., latn for Latin script, dflt for default language). A feature tag will fail to execute if its associated script tag is invalid.

Step 3: Run FontForge's Built-in Validator

FontForge includes an automated validator to detect structural errors, including malformed OpenType tables and broken lookups.

  1. Close the Font Info window by clicking OK.
  2. Go to Element > Validation > Validate.
  3. In the dialog that appears, ensure validation checks for OpenType tables and glyph naming are enabled, then click Validate.
  4. Examine the results window. If a feature references missing glyphs, has invalid script/language syntax, or violates table structures, FontForge will flag it with an error or warning pointing directly to the offending lookup.

Step 4: Verify via the Metrics Window

To ensure that layout engines will activate the tag properly:

  1. Open the Metrics window by navigating to Metrics > New Metrics Window.
  2. Type the character sequence targeted by your feature.
  3. Select View > Features from the Metrics menu to view all active and available OpenType features.
  4. Verify that your feature tag appears in the list and can be toggled on and off as expected. If the tag does not appear, check the lookup definition in Font Info to ensure it has valid subtable data and glyph mappings.
