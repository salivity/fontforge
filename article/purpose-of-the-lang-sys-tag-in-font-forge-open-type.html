Purpose of the LangSys Tag in FontForge OpenType

The LangSys (Language System) tag in FontForge's OpenType dialog defines language-specific typographical rules by linking OpenType layout features directly to specific languages within a writing script. This article explains the hierarchy, purpose, and practical utility of LangSys tags in font design, detailing how type designers use them in FontForge to manage language-dependent glyph substitutions and positioning rules.

The OpenType Hierarchy

To understand the purpose of the LangSys tag, you must understand how OpenType organizes advanced typographic tables (GSUB for glyph substitution and GPOS for glyph positioning). FontForge structures these tables using a four-tier hierarchy:

  1. Script: The writing system (e.g., Latin latn, Cyrillic cyrl, Arabic arab).
  2. LangSys: The specific language system using that script (e.g., Default dflt, Turkish TRK, Romanian ROM).
  3. Feature: The typographical function to apply (e.g., Ligatures liga, Small Caps smcp, Localized Forms locl).
  4. Lookup: The actual data table containing the glyph transformation instructions.

The LangSys tag acts as the essential bridge between the broad writing system and the granular typographical features.

Primary Purposes of the LangSys Tag

1. Enabling Localized Forms (locl)

Languages sharing the same script often have conflicting typographic requirements. The LangSys tag allows FontForge to apply the locl feature strictly where intended without corrupting the rendering of other languages.

  • Turkish and Azeri (TRK, AZE): These languages distinguish between dotted i and dotless ı in both lowercase and uppercase. A standard font might capitalize i to I and ı to I. Assigning a specific LangSys tag ensures that i correctly capitalizes to İ with a dot.
  • Romanian and Moldavian (ROM, MOL): Standard Central European fonts historically substituted the comma-accented ș and ț with cedilla characters ş and ţ. A LangSys tag targeting Romanian allows the font to substitute true comma-below glyphs without affecting Turkish contexts where cedillas are correct.
  • Dutch (NLD): In Dutch, the diphthong ij is treated as a single letter. A Dutch LangSys tag can automatically substitute an acute-accented íj́ combination or a specialized ligature when accented.

2. Suppressing Inappropriate Features

Certain languages forbid features that are standard in others. For example, standard decorative ligatures like "fi" and "ffi" can alter the pronunciation or violate orthography in languages such as Turkish, where an "fi" ligature destroys the crucial dot on the "i". Using the LangSys tag, a designer can instruct FontForge to enable the liga feature by default, while excluding or disabling it under the TRK language system.

3. Defining the <Default> Fallback

Within FontForge's OpenType table dialog, every script includes a <Default> language entry (tag dflt). The purpose of this default tag is to define the universal baseline features for any text using that script whose language is unspecified or not explicitly differentiated.

Features linked to the <Default> LangSys apply automatically to all languages unless an explicit LangSys tag is created to override or supplement them. When creating a custom LangSys tag in FontForge, you can configure whether to inherit the default features or establish a standalone ruleset.
